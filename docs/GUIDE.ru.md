## 1. О Ghost Sphere

**Ghost Sphere** — это единый центр управления, который объединяет всю экосистему **Remnawave** в одном тёмном, технологичном и быстром интерфейсе. Из одной панели вы управляете:

- **нодами** (VPN-серверами с Xray),
- **конфигурациями Xray** (профили, inbounds, маршрутизация),
- **пользователями** и их ключами доступа,
- **подписками** (выдача конфигов клиентам),
- **хостами** (точками подключения),
- **сквадами** (группами доступа),
- **API-токенами и секретами**,
- **интеграциями** (боты, магазины, мониторинг),
- **бэкапами** и **хранилищем шаблонов**.

Платформа спроектирована так, чтобы быть в разы удобнее, профессиональнее и технологичнее существующих решений: тёмная тема **Ghost OS**, командная палитра `Ctrl+K`, живые метрики, аккуратные анимации и полная локализация **RU / EN**.

> **Демо-режим** позволяет изучить весь интерфейс на демонстрационных данных без реальной панели — идеально для знакомства и обучения.

## 2. Архитектура

Ghost Sphere — **самодостаточный форк движка Remnawave**. Никакой внешней панели: база, движок, панель и ноды — всё ваше.

```
┌──────────────┐  /api ·   ┌──────────────┐  локально  ┌────────────────────┐   mTLS :2222   ┌────────────────┐
│ Ghost Sphere │  Bearer   │ Ghost Sphere │ ─────────► │ Ghost Sphere Engine│ ─────────────► │ Ghost Sphere   │
│     Web      │ ────────► │     BFF      │            │ (форк backend RW)  │                │ Nodes (Xray)   │
│ React+Mantine│ ◄──────── │  (NestJS)    │ ◄───────── │ NestJS + Prisma    │ ◄───────────── │                │
└──────────────┘           └──────────────┘            └─────┬───────┬──────┘                └────────────────┘
                                                             │       │
                                                   ┌─────────▼─┐ ┌───▼─────────┐
                                                   │ PostgreSQL│ │ Redis/Valkey│
                                                   └───────────┘ └─────────────┘
```

| Компонент | Что это | Технологии |
| --- | --- | --- |
| **Ghost Sphere Web** | Премиальный интерфейс (SPA), наш дизайн | React 19, Vite, Mantine 8, TanStack Query, Zustand, i18next, Framer Motion, Monaco |
| **Ghost Sphere BFF** | API-слой для интерфейса (удобные DTO, прокси логина) | NestJS 11, Axios |
| **Ghost Sphere Engine** | **Наш движок** — полноценный форк backend Remnawave | NestJS 11, Prisma, PostgreSQL, Redis, BullMQ |
| **Ghost Sphere Nodes** | Форк node Remnawave (Xray-агент на серверах) | Xray-core, mTLS |

**Ключевая идея:** движок (Engine) — это **наша собственная панель** на нашей базе данных, а не обращение к чужой Remnawave. Вы логинитесь напрямую в свой движок (админ-логин), а BFF лишь форвардит ваш JWT и приводит ответы к удобным для интерфейса DTO. Весь стек поднимается одной командой `docker compose up`.

## 3. Установка

### 3.1. Docker (рекомендуется)

Требования: установленные **Docker** и **Docker Compose**.

```bash
cd SPHERE-GHOST
docker compose up -d --build
```

Откройте **http://localhost:8080**.

- Порт меняется переменной окружения `GHOST_SPHERE_PORT` (по умолчанию `8080`):
  ```bash
  GHOST_SPHERE_PORT=9000 docker compose up -d --build
  ```
- Поднимаются два контейнера:
  - `ghost-sphere-web` — nginx, отдаёт интерфейс и проксирует `/api` на ядро;
  - `ghost-sphere-core` — шлюз (внутренний порт `8088`).

Остановить:

```bash
docker compose down
```

### 3.2. Локальная разработка

Требования: **Node.js 20+** (рекомендуется 22), npm.

```bash
# Установка зависимостей обоих приложений
npm run install:all

# Терминал 1 — ядро (NestJS)
npm run dev:api          # http://127.0.0.1:8088

# Терминал 2 — интерфейс (Vite)
npm run dev:web          # http://127.0.0.1:4173
```

Vite автоматически проксирует `/api` на ядро (`http://127.0.0.1:8088`), поэтому ничего дополнительно настраивать не нужно.

### 3.3. Продакшен за reverse proxy (HTTPS)

Рекомендуется выставлять Ghost Sphere наружу только по HTTPS. Пример для **Caddy**:

```caddy
sphere.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

Пример для **Nginx** (фронт перед контейнером web):

```nginx
server {
    listen 443 ssl http2;
    server_name sphere.example.com;
    ssl_certificate     /etc/letsencrypt/live/sphere.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/sphere.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

### 3.4. Переменные окружения

Все значения задаются в `docker-compose.yml` (блок `environment`) и переопределяются переменными окружения.

**Движок (Engine):**

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `DATABASE_URL` | `postgresql://ghost:…@db:5432/ghostsphere` | Подключение к PostgreSQL |
| `REDIS_HOST` / `REDIS_PORT` | `redis` / `6379` | Redis / Valkey |
| `JWT_AUTH_SECRET` | `ghost_sphere_auth_secret_0001…` | **Сменить в проде!** Подпись JWT |
| `JWT_API_TOKENS_SECRET` | `ghost_sphere_api_secret_0001…` | **Сменить в проде!** |
| `DISABLE_FRONTEND` | `true` | Движок не отдаёт фронт (его отдаёт `web`) |
| `SUB_PUBLIC_DOMAIN` | `localhost:8080/api/sub` | Домен подписок |
| `METRICS_USER` / `METRICS_PASS` | `admin` / `admin` | Доступ к метрикам |

**BFF (`api`):** `PORT=8088`, `ENGINE_URL=http://backend:3000`.
**Интерфейс:** `VITE_API_BASE=/api`, `VITE_APP_VERSION=0.0.1`.
**База:** `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, плюс `GHOST_SPHERE_PORT` (внешний порт web, по умолчанию `8080`).

## 4. Первый вход

Ghost Sphere — самодостаточный: вы входите в **свой** движок, никакой внешней панели не требуется.

### 4.1. Создание первого администратора

1. После `docker compose up -d --build` откройте **http://localhost:8080**.
2. На экране входа переключитесь на вкладку **«Регистрация»**.
3. Введите **имя администратора** и **пароль** (минимум 4 символа) → **«Создать администратора»**.
4. Вы сразу окажетесь на дашборде «Обзор сферы». Это первый и главный аккаунт панели.

### 4.2. Последующие входы

1. Откройте панель, вкладка **«Вход»**.
2. Введите имя администратора и пароль → **«Войти в панель»**.

> Технически: интерфейс отправляет логин в `POST /api/auth/login` (через BFF → движок), получает JWT и хранит его локально в браузере; далее JWT прикладывается ко всем запросам. Никакой внешний токен вводить не нужно.

### 4.3. Демо-режим

Если панели ещё нет или вы хотите просто осмотреться — нажмите **«Войти в демо-режиме»**. Загрузится полностью рабочий интерфейс на демонстрационных данных (ноды, пользователи, конфиги, графики). Все действия в демо безопасны и не затрагивают реальную инфраструктуру.

### 4.4. Хранение токена и безопасность

- Токен и адрес панели хранятся **локально в вашем браузере** (localStorage) и при работе в live-режиме передаются только вашему ядру Ghost Sphere, которое проксирует запросы к панели.
- Сбросить локальные данные можно в **Настройки → О программе → Опасная зона → «Сбросить локальные данные»** или кнопкой **Выйти**.
- Для продакшена обязательно используйте HTTPS (см. п. 3.3).

## 5. Навигация по интерфейсу

Слева — **боковое меню**, сгруппированное по разделам:

- **Обзор** → Обзор сферы
- **Инфраструктура** → Ноды, Конфигурации, Хосты
- **Доступ и подписки** → Пользователи, Подписки, Сквады, Ключи и токены
- **Рост и интеграции** → Интеграции, Бэкапы, Хранилище
- **Система** → Настройки, Руководство

Сверху — **верхняя панель**:

- **Поиск / командная палитра** — нажмите `Ctrl + K` (или `Cmd + K`), чтобы мгновенно перейти к любому разделу или выполнить быстрое действие (создать ноду, пользователя, бэкап, сменить язык).
- **Индикатор режима** — `Демо` или `В сети`.
- **Язык** — переключение **RU / EN** в один клик.
- **Уведомления**, **Настройки**, **меню профиля** (выход).

Внизу бокового меню — мини-виджет **состояния сферы** (здоровье, ноды онлайн, пользователи в сети).

## 6. Обзор сферы (дашборд)

Главный экран показывает состояние инфраструктуры в реальном времени:

- **Карточки метрик:** всего пользователей (с трендом), сейчас в сети, нод в сети, трафик за месяц — со спарклайнами.
- **Мощность сферы** — сводный индикатор (кольцо) на основе доли активных нод и пользователей, плюс **CPU**, **ОЗУ** и **аптайм**.
- **Рост пользователей** — график во времени (всего / активных).
- **Топ нод по нагрузке** — столбчатый график трафика по нодам.
- **Последние события** — лента действий (подключения нод, создание пользователей, бэкапы и т. д.).
- **Быстрые действия** — добавить ноду / пользователя / конфиг / бэкап.

Частота обновления данных настраивается в **Настройки → Общие → Интервал опроса**.

## 7. Ноды

Раздел управления VPN-серверами. Доступны два вида: **карточки** и **таблица** (переключатель справа сверху).

### Что показывает карточка ноды

- Флаг страны, имя, адрес и порт.
- Статус: **Подключена** / **Подключается** / **Отключена** / **Отключена оператором**.
- Версия Xray, пользователи онлайн.
- Метры **CPU**, **ОЗУ**, **использованного трафика** (с лимитом, если задан).
- Профиль конфигурации и аптайм Xray.

### Создание ноды

1. Нажмите **Добавить ноду**.
2. Заполните: **Имя**, **Адрес** (IP/домен), **Порт** (обычно `2222`), **Страна** (двухбуквенный код, напр. `DE`), **Профиль конфигурации**.
3. Нажмите **Создать**. Нода появится в статусе «Подключается» и подключится автоматически, как только агент на сервере станет доступен.

### Мастер установки ноды

Для нового сервера используйте **Установить ноду**:

1. Подготовьте чистый сервер (**Debian 12 / Ubuntu 22.04+**), root-доступ.
2. Скопируйте **команду установки** и выполните её на сервере под root.
3. Вставьте сгенерированный **SECRET_KEY** (он создаётся индивидуально для ноды).
4. Откройте порт **`2222/tcp`** для IP вашей панели и нажмите **Подключиться**.

Скрипт `scripts/install-node.sh` устанавливает Docker (если нужно), создаёт `docker-compose.yml` ноды с `SECRET_KEY` и запускает агент:

```bash
SECRET_KEY="<вставьте из мастера>" \
bash <(curl -Ls https://raw.githubusercontent.com/.../install-node.sh)
```

### Действия с нодой

Через меню «⋮» на карточке/строке:

- **Включить / Отключить** — управление доступностью.
- **Перезапустить** — перезапуск Xray на ноде.
- **Сбросить трафик** — обнуление счётчика использованного трафика.
- **Удалить** — удаление ноды (с подтверждением).

### Множитель потребления

Параметр **множитель потребления** позволяет учитывать «дорогой» трафик премиальных локаций: при множителе `2` каждый гигабайт на этой ноде списывает у пользователя вдвое больше.

### Если нода не подключается

1. Проверьте, что порт **`2222/tcp`** открыт для IP панели (`ufw allow from <PANEL_IP> to any port 2222`).
2. Убедитесь, что контейнер ноды запущен: `docker ps`, `docker logs ghost-sphere-node`.
3. Проверьте корректность **SECRET_KEY** (он одноразово генерируется для конкретной ноды).
4. Посмотрите **«Последний статус»** на карточке — там отображается причина.

## 8. Конфигурации Xray

Профили конфигураций содержат полный JSON Xray (`inbounds`, `outbounds`, `routing`, `dns`, `policy` и т. д.). Один профиль можно применить сразу к нескольким нодам — изменения раскатываются автоматически.

### Профили

- На вкладке **Профили** — карточки со списком инбаундов, числом нод, использующих профиль, и датой обновления.
- Откройте профиль, чтобы войти в **редактор**.

### Редактор (Monaco)

- Полноценный редактор JSON с подсветкой синтаксиса и темой **Ghost Dark**.
- **Автодополнение и проверка по схеме Xray** — подсказки по ключам и значениям.
- **Проверить** — семантическая валидация: дубли тегов, отсутствие протокола, `reality` без `realitySettings` и т. д. Результат выводится в боковой панели (ошибки/предупреждения).
- **Форматировать** — приведение JSON к читаемому виду.
- **X25519 ключи** — генерация пары ключей для **REALITY** одной кнопкой.
- **Сохранить** — применяет профиль к связанным нодам. Несохранённые изменения подсвечиваются.

### Сниппеты

Сниппеты — переиспользуемые фрагменты JSON (например, правило блокировки рекламы), которые вставляются в конфиг через плейсхолдер `{{snippet:имя}}`. Это упрощает поддержку одинаковых блоков в разных профилях.

## 9. Хосты

**Хост** — это точка подключения, которую в итоге получает клиент (определяет адрес, порт, маскировку и параметры безопасности).

Поля хоста:

- **Название (remark)** — отображается в клиенте.
- **Адрес**, **Порт**.
- **Безопасность**: `REALITY`, `TLS` или `none`.
- **SNI**, **Host**, **Path**, **ALPN**, **Отпечаток (fp)**.
- **Профиль** и **Inbound**, к которым привязан хост.
- Переключатель включения/отключения.

Хосты связывают пользователей (через сквады) с конкретными инбаундами на нодах. Один пользователь может получать несколько хостов в своей подписке.

## 10. Пользователи и ключи

Раздел управления клиентами VPN.

### Метрики сверху

Всего пользователей, активных, в сети, с исчерпанным лимитом/истёкших.

### Создание пользователя (ключа)

1. Нажмите **Создать пользователя**.
2. Заполните:
   - **Имя пользователя** — уникальный логин.
   - **Лимит трафика (ГБ)** — `0` означает безлимит.
   - **Срок (дней)** — через сколько дней истечёт доступ.
   - **Стратегия сброса** — `Без сброса`, `Ежедневно`, `Еженедельно`, `Ежемесячно` (когда обнуляется счётчик трафика).
3. Нажмите **Создать ключ**. Пользователь сразу получает ссылку подписки.

### Поля и статусы

- **Статус:** `Активен`, `Отключён`, `Лимит исчерпан`, `Истёк`.
- **Трафик:** использовано / лимит (метр).
- **Действует до**, **онлайн-статус**, **последний вход**.
- **Сквады**, **Устройства (HWID)** и их лимит, **Telegram ID**, **email**.

### Действия с пользователем

- **Копировать ссылку подписки** (иконка копирования прямо в таблице).
- **Включить / Отключить**.
- **Сбросить трафик**.
- **Перевыпустить ключ (revoke)** — генерирует новый `shortUuid`; старая ссылка перестаёт работать (используйте при компрометации).

### Поиск и постранично

Поле поиска фильтрует по имени/почте; список разбит на страницы по 12.

## 11. Подписочная система (полное описание)

Подписка — это **персональная ссылка пользователя**, по которой VPN-клиент скачивает актуальную конфигурацию (список серверов и параметры подключения). Это сердце пользовательского опыта: вы создаёте ключ — клиент получает рабочий конфиг и подключается.

### 11.1. Как устроена ссылка

Формат:

```
https://<домен-подписки>/<shortUuid>
https://<домен-подписки>/<shortUuid>/<тип-клиента>
```

- `shortUuid` — короткий уникальный идентификатор пользователя (генерируется при создании, меняется при «перевыпуске»).
- `<тип-клиента>` — необязательная часть, принудительно задающая формат: `json`, `v2ray-json`, `clash`, `mihomo`, `singbox`, `stash`.
- Домен подписки настраивается на стороне Remnawave (`SUB_PUBLIC_DOMAIN`) и обычно указывает на «страницу подписки».

В Ghost Sphere готовую ссылку можно скопировать в разделе **Пользователи** (иконка копирования) или увидеть в карточке пользователя.

### 11.2. Поддерживаемые форматы выдачи

| Формат | Тип в системе | Для каких клиентов |
| --- | --- | --- |
| **Xray Base64 (v2ray)** | `XRAY_BASE64` | v2rayNG, v2rayN, Streisand, Shadowrocket, Nekoray |
| **Xray JSON** | `XRAY_JSON` | Happ, клиенты с поддержкой raw-JSON Xray |
| **Clash / Clash Meta** | `CLASH` | Clash for Windows, ClashX, Clash Meta |
| **Mihomo** | `MIHOMO` | Mihomo (Clash.Meta ядро) |
| **Sing-box** | `SINGBOX` | sing-box, Hiddify, Karing |
| **Stash** | `STASH` | Stash (iOS) |

### 11.3. Клиентские приложения по платформам

| Платформа | Рекомендуемые приложения |
| --- | --- |
| **Android** | Happ, v2rayNG, Hiddify, NekoBox, Clash Meta for Android |
| **iOS** | Happ, Streisand, Shadowrocket, Stash, Sing-box |
| **Windows** | Hiddify, v2rayN, Nekoray, Clash Verge |
| **macOS** | Happ, Hiddify, ClashX Meta, Sing-box |
| **Linux** | Nekoray, sing-box, Clash Meta |

### 11.4. Автоопределение формата (SRR — Subscription Response Rules)

Когда клиент запрашивает ссылку **без указания типа**, система смотрит на заголовок `User-Agent` и по **правилам ответа (SRR)** автоматически отдаёт нужный формат. Например, запрос от `clash` получит Clash-конфиг, от `sing-box` — Sing-box, а из браузера — HTML-страницу подписки.

Правила настраиваются в **Подписки → Правила ответа (SRR)** (редактор правил сопоставления `User-Agent → формат`).

### 11.5. Шаблоны выдачи

**Шаблон** определяет, как именно рендерится конфиг конкретного формата (какие поля, сортировка, имена серверов, параметры). В **Подписки → Шаблоны** доступны шаблоны для Xray JSON, Clash/Mihomo, Sing-box, Stash. Их можно редактировать под свой бренд и требования.

> Готовые шаблоны можно взять из раздела **Хранилище → Шаблоны подписок** и применить в один клик.

### 11.6. Настройки подписки

В **Подписки → Настройки**:

- **Заголовок профиля** — имя, которое увидит пользователь в клиенте (например, `Ghost Sphere VPN`).
- **Интервал обновления (ч)** — как часто клиент будет обновлять конфиг (рекомендуется 12–24 ч).
- **Ссылка поддержки** — показывается в клиенте/на странице.
- **Перемешивать хосты** — рандомизация порядка серверов для равномерной нагрузки.

### 11.7. Страница подписки (для браузера)

Если пользователь открывает ссылку **в браузере**, он видит не «сырой» конфиг, а аккуратную **страницу подписки**: название профиля, остаток трафика и срок, **QR-код**, кнопки **«Открыть в приложении»** и **инструкции по установке** под каждую платформу. Это самый удобный способ для конечного пользователя.

Внешний вид страницы настраивается в **Подписки → Страницы подписки** (и шаблоны в **Хранилище → Страницы подписок**).

### 11.8. Лимит устройств (HWID)

Для каждого пользователя можно задать **лимит устройств (HWID)**. При включённом контроле система запоминает «отпечатки» устройств и не позволяет подключиться сверх лимита. Текущее число привязанных устройств видно в карточке пользователя; лимит задаётся при создании/редактировании.

### 11.9. Перевыпуск ключа (revoke)

Если ссылка скомпрометирована, нажмите **Перевыпустить ключ** в действиях пользователя. Сгенерируется новый `shortUuid`, старая ссылка немедленно перестанет работать. Пользователю нужно будет импортировать новую ссылку.

### 11.10. Как пользователь подключается (пошагово)

**Вариант А — через страницу подписки (проще всего):**

1. Откройте ссылку подписки в браузере телефона.
2. Нажмите **«Открыть в приложении»** (например, Happ) — приложение само импортирует профиль.
3. Нажмите «Подключиться».

**Вариант Б — вручную (любой клиент):**

1. Скопируйте ссылку подписки.
2. В приложении выберите **«Добавить из подписки / URL»** (Subscription / Import from URL).
3. Вставьте ссылку → сохраните → обновите подписку.
4. Выберите сервер и подключитесь.

**Пример для v2rayNG (Android):** «+» → «Импорт конфигурации из подписки» → вставить URL → меню «Обновить подписки» → выбрать сервер → подключиться.

**Пример для Hiddify:** «Добавить профиль из URL» → вставить ссылку → профиль появится со списком серверов.

### 11.11. Устранение неполадок подписки

| Симптом | Причина и решение |
| --- | --- |
| Пустой список серверов | Нет активных хостов/инбаундов для сквада пользователя. Проверьте **Хосты** и **Сквады**. |
| Клиент не обновляет конфиг | Слишком большой интервал обновления или клиент кэширует — обновите подписку вручную. |
| «Неверный формат» в клиенте | Клиент получил не тот формат. Укажите тип в ссылке (`/clash`, `/singbox`) или настройте **SRR**. |
| Подключение есть, интернета нет | Проблема на ноде (Xray/маршрутизация). Проверьте **Ноды** и **Конфигурации**. |
| «Превышен лимит устройств» | Сработал HWID-лимит. Увеличьте лимит или отвяжите старое устройство. |

## 12. Сквады

**Сквады** — это группы доступа, которые связывают пользователей с инбаундами (а значит, с хостами и серверами).

- **Внутренние сквады** — основной механизм: определяют, к каким инбаундам имеют доступ участники, и какие хосты исключены.
- **Внешние сквады** — переопределения выдачи/брендирования подписки для отдельных групп (например, для реселлеров).

В карточке сквада видны число участников и список инбаундов. Создавайте сквады под тарифы (Premium / Standard / Trial) и распределяйте пользователей.

## 13. Ключи и токены

Три вкладки:

### API-токены

Токены для программного доступа к панели (их использует и само ядро Ghost Sphere, и боты/интеграции). Создавайте именованные токены, копируйте значение (показывается один раз), отзывайте ненужные.

### Ключи нод (mTLS)

Сертификаты и `SECRET_KEY` для установки нод. Здесь же — генерация пары **X25519** (используется для REALITY).

### Хранилище секретов

Зашифрованное хранилище для паролей, токенов ботов и ключей провайдеров (`TELEGRAM_BOT_TOKEN`, `CLOUDFLARE_API_KEY`, `S3_SECRET_KEY` и т. п.). Значения скрыты по умолчанию, открываются по кнопке и копируются в один клик.

## 14. Интеграции

Раздел подключает к сфере остальные части экосистемы. Карточки сгруппированы по категориям, у каждой — статус и индикатор здоровья.

| Интеграция | Назначение |
| --- | --- |
| **Telegram-магазин** | Продажа подписок, тарифы, платежи, рефералы в Telegram |
| **Админ-бот** | Управление пользователями/нодами из Telegram |
| **Cloudflare-ноды** | Автоматическое DNS по здоровью нод |
| **Xray Checker** | Мониторинг работоспособности прокси/подписок |
| **Whitebox** | Проверка реальной достижимости через VPN-туннель |
| **MCP-сервер** | Управление панелью через LLM (Cursor / Claude) |
| **Бэкап-агент** | Резервные копии в Telegram / S3 / Google Drive |
| **WARP** | Нативный Cloudflare WARP как WireGuard-интерфейс на нодах |

Чтобы подключить интеграцию: откройте карточку → **Подключить** → укажите эндпоинт/секрет (если требуется). Индикатор здоровья покажет, что связь работает.

## 15. Бэкапы и восстановление

- **Создать бэкап** — выберите назначение (**Локально / S3 / Google Drive / Telegram**) и компоненты (**БД**, **файлы панели**, **боты**).
- **Автоматические бэкапы** — включите и задайте **cron-расписание** (например, `0 4 * * *` — каждый день в 04:00) и срок хранения (число копий).

> Рекомендуется хранить бэкапы во внешнем месте (S3 / Telegram), а не только локально на сервере панели.

## 18. Безопасность

- Выставляйте Ghost Sphere наружу **только по HTTPS** (reverse proxy + сертификат).
- Используйте отдельный **API-токен** для Ghost Sphere; при подозрении на утечку — отзовите его в панели и создайте новый.
- Открывайте порт нод **`2222/tcp`** только для IP панели, а не для всего интернета.
- Храните секреты ботов/провайдеров в **Хранилище секретов**, а не в открытом виде.
- Регулярно делайте **бэкапы** и проверяйте их восстановление.
- Включайте **HWID-лимиты**, чтобы один ключ не «расшаривали» на десятки устройств.

## 20. Частые вопросы и устранение неполадок

**В live-режиме «Нет подключения к панели» / ошибки запросов.**
Проверьте адрес панели и токен (Настройки → Панели), доступность панели по сети и валидность токена в Remnawave.

**Не открывается интерфейс на :8080.**
Убедитесь, что контейнеры запущены: `docker compose ps`, посмотрите логи: `docker compose logs web` и `docker compose logs api`.

**Графики «Рост пользователей»/«Трафик» пустые в live-режиме.**
Эти ряды строятся из исторических данных панели; на свежей инсталляции истории ещё нет. Дашборд-метрики и «Топ нод» при этом работают.

**Безопасно ли хранить токен в браузере?**
Токен остаётся локально и уходит только вашему ядру Ghost Sphere. Для дополнительной защиты используйте HTTPS и при необходимости `X-Api-Key` (Caddy/tinyauth).

**Можно ли подключить несколько панелей?**
Да. Ядро stateless: достаточно переключить активную панель (учётные данные передаются заголовками). Версия 0.0.1 закладывает основу для мультипанельного управления.

**Зачем нужен демо-режим?**
Чтобы изучить весь функционал без реальной инфраструктуры — для оценки, обучения и демонстраций.
